# BUG-0037: Web E2E lane served stale frontend assets

- **Status:** fixed
- **Impact (user-side):** Blocks-Completion
- **Severity:** High · **Priority:** P1
- **Persona Affected:** QA operator
- **Journey Step:** Phase C automated release gate
- **Scenarios:** QA infrastructure; no product scenario
- **Found:** 2026-07-11 · **Report:** `docs/qa/reports/2026-07-11-agent-details.md`

## Summary

`make test-e2e-web` reused `web/dist` whenever `web/dist/index.html` already existed. A source change could therefore be tested against an older browser bundle, producing false failures or, more dangerously, certifying stale shipped behavior.

## Reproduction

1. Leave a previously built `web/dist/index.html` in the worktree.
2. Change a visible web route without rebuilding the bundle.
3. Run `make test-e2e-web`.

**Expected:** The daemon-served Playwright lane builds and serves the current frontend source.
**Actual:** `ensureWebAssets` treated file existence as freshness and skipped `WebBuild`. The first Task 09 run showed current test source driving an older Agents UI without Page Head, Rows/Cards, or current topbar actions; 15 cross-area scenarios timed out.

## Fix

- **Root cause:** `magefiles/e2e.go` used `os.Stat(webDistIndex)` as the only freshness check.
- **Fix commit:** `f7d8a96`.
- **Harness fix:** every E2E lane that requires web assets now runs `CodegenCheck` and a fresh `WebBuild` before preparing the daemon-served environment.
- **Contract cleanup:** current Agents E2E selectors use the Filters component's real ARIA `option` contract, and the empty-fleet state explicitly controls the API response instead of assuming an empty mock-agent addition removes global definitions.

## Verification

- The next `make test-e2e-web` invocation visibly ran `vite build` before Playwright.
- After current-contract fixes, the complete daemon-served lane passed all 70 tests.
- `make test-e2e-runtime` also passed under the fresh-asset harness.
