AGH · Settings design system

Settings, redesigned for people — not just operators

Settings is the one surface where AGH talks to the person, not the operator. This spec replaces the current dual-rail, jargon-chip, twelve-section pattern with a focused takeover shell, a plain-language row vocabulary, and progressive disclosure for everything mechanical. It reuses the established prototype canon (topbar, page head, panelbox, listing toolbar, sheet) — only the settings-specific layer is new.

01

Principles

Five rules that produced every decision below. When a migration question is not covered by this spec, answer it with these.

P-01Written for the person, not the process

Every label and description says what the setting does to the user’s work, in a sentence. Mechanism names (config.toml, policies, thresholds) never appear in a primary row — they live one level down, in Advanced.

P-02One navigation at a time

Settings takes over the window with its own sidebar; the app sidebar yields. Two parallel rails was the single biggest source of visual pollution in the current screens.

P-03Jargon earns its place through disclosure

Operator depth is not deleted — it is demoted. Circuit breakers, apply records, delivery tuning, env policies: all reachable, all one fold away, none competing with the primary flow.

P-04Saving is visible and honest

The three real persistence models (page draft, per-item, immediate) stay exactly as the daemon implements them — the UI just makes each one legible: a floating save bar, a sheet with its own Save, a switch that just works.

P-05Truthful UI, calm color

Every row maps to a daemon-persisted value; nothing is invented to fill a layout. Accent appears only on the active nav item and the primary action. State is carried by the signal palette plus text, never color alone.

02

Shell — the settings takeover

Entering Settings swaps the app shell for a dedicated one: a 264px settings sidebar on --canvas-soft, the standard 48px topbar with breadcrumb, and a centered content column. “Back to app” (and Esc with no dialog open) returns to the previous route. This replaces the current pattern where the app sidebar and a second w-56 settings rail render side by side.

04

Page anatomy

Every settings page = head → (optional restart notice) → setting groups → (optional Advanced) → save bar when the page uses draft semantics. The head keeps the canon icon + 1.4rem title and gains a one-line description; the old StatusLine count dump becomes a quiet dotsep meta row.

Restart notice — replaces RestartBanner

Restart needed Permission changes apply after the daemon restarts. Running sessions keep their current rules until then.

Warning tint, no border, sits under the head. It states what happens if you don’t act — never just “pending restart”. Same component with --danger-tint serves hard failures.

05

Setting rows — the core vocabulary

One row = one decision. Label + plain-language consequence on the left, a single control on the right, 54px minimum, hairline separators inside a .panelbox. Six variants cover every field in all nine current pages.

Switch row

Immediate boolean. The description states the consequence, not the flag name.

Select row

One choice from a short list. Options are humanized; machine values live in Advanced.

Number row

Numeric with its unit outside the field, mono, right-aligned.

seconds
Action row

A verb the daemon performs now. Button shows progress inline.

Link row

Leads somewhere else — a marketplace, a top-level route, a history sheet.

Read-only row config.toml

Facts the daemon owns. Value in mono; provenance chip only inside Advanced.

~/.agh/config.toml

The jargon chip rule

Before — every row
Session timeout config.toml seconds optional

session.timeout_seconds

After — primary row
End idle sessions after

A session with no activity for this long is ended and kept in history.

The current SettingsFieldRow hint chips (CONFIG.TOML, OPTIONAL, DEFAULT, IANA, SECONDS, TRUST, PI…) are deleted from primary rows. The only survivor is the mono .provchip, allowed exclusively inside Advanced folds and sheet Advanced sections, where it names the real key (env_policy, session.timeout).

06

Controls

All controls come from the packages/ui lineage: 32px inputs and selects on --elevated, the 32×18 switch, and choice cards for the few decisions that deserve explanation space. No new control families.

Choice cards — for modes with consequences

Use choice cards when a wrong pick has real consequences (permission mode, provider sign-in method). Everything else uses the plain select. Selection state is neutral (glaze + inset ring + check) — accent is not a selection color. The machine value sits at the card foot in 9.5px mono --faint: honest, but whispering.

07

Save & apply

The daemon has three persistence models. They stay — the redesign only standardizes how each one looks, and removes the ambiguity of per-section “Apply” buttons scattered mid-page.

Unsaved changes
Saved

Floating save bar: sticky at bottom 24px inside the content column, --elevated + overlay shadow, hidden until dirty. States: dirty (warning dot) → saving → saved (success dot, auto-dismiss ~1.2s) → restart notice if the change requires it.

08

Progressive disclosure — the Advanced fold

Each page may end with exactly one Advanced fold (chevron toggle, closed by default). It holds the operator layer for that page. Nothing inside it is required for everyday use; everything inside it is honest about its mechanism, including .provchip provenance.

11

Implementation checklist

P0 — blocking

Takeover shell only (no app sidebar inside /settings) · nav = 3 groups, 9 unchanged routes · every primary row has a consequence sentence · zero uppercase jargon chips outside Advanced · save bar appears only when dirty and names its state · restart notice states the consequence · accent limited to active nav + primary action · all controls keyboard-operable with visible focus · every value maps to a daemon-persisted field.

P1 — required next

Sidebar search filters by per-section keywords · below-900px chip strip parity with production · per-model save matrix (07) implemented exactly · Providers listing ships Rows|Cards toggle · empty and error states for lists and immediate-save failures · Esc exits Settings when no dialog or sheet is open.
