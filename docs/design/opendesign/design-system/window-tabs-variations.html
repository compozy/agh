AGH Design System · Exploration — pick one

Window tabs — three directions

cmux proves the model: splits divide the desktop, and each surface still holds its own tab row, so one window multiplexes many terminals. AGH windows can't do this today — the 44px head hosts exactly one identity (S1) and two bars maximum (S2). This file proposes three anatomies that add per-window tabs able to host any surface — a route, a drilled-in state, a live session document — while keeping the existing head vocabulary. All demos are live: click tabs to switch, × to close, + to add. In every direction a single-tab window renders exactly today's chrome — tabs cost nothing until the second tab exists. The winner gets folded into 02 · OS Shell §02 and os/os-v2.

00

What has to survive

Whatever anatomy wins, the existing contracts still apply per surface: identity renders once (glyph + 13px/600 title, or breadcrumb at depth, or pulsing dot for documents) · route tabs sit after the title · status chip + ≤2 actions on the trail · optional 38px tools strip · a guaranteed drag gutter. The three directions differ only in where the tab switcher lives and what each placement costs.

01

A · Fused — tabs are the head

Safari / Arc compact

No new bar. Tab segments live inside the 44px head itself; the active tab is the window identity — it carries the glyph, the 13px/600 title and the count, reusing the .w2-tab selection vocabulary at 30px. Trail status and actions swap with the active tab. Cheapest chrome of the three, and the tightest fit: route tabs relocate to the strip, and the drill-in trail compresses to a back chevron inside the tab.

02

B · Deck — a thin tab row above the head

closest to the cmux reference

The cmux model, translated to AGH chrome: a 37px deck on the window's rail-dark edge holds the window controls, the tabs and the drag region; the 44px head below belongs entirely to the active tab — identity, route tabs, breadcrumb at depth, status and actions all unchanged from today's contract. The active tab fuses with the head surface, browser-style. With one tab the deck vanishes and controls return to the head: exactly today's window.

03

C · Rail — a documents column

Zed / Arc sidebar

Tabs project vertically: a 208px rail on the window's left edge lists every open surface as a 30px row — state dot or glyph, label, attention badge, × on hover — with the active row marked by the same inset accent bar the ⌘K palette uses. The head keeps today's full contract for the active tab. Built for session-heavy work: dozens of tabs stay readable. The rail collapses to a 46px icon strip — manually, or automatically when the window is narrower than 600px (the same row ⇄ sidebar adaptation contracted for route tabs).

T1Tabs cost nothing until the second one. Every direction renders a single-tab window exactly as today's anatomy; tab chrome mounts at the second tab (⌘T) and unmounts back.
T2A tab hosts any surface. Routes, drilled-in states and session documents mix freely in one window; each tab keeps its own navigation stack, strip and trail. Glyphs identify routes; state dots + badges identify live work (S9 holds — selection is neutral, accent only for state, badges and the primary action).
T3Drag out, drop in. Dragging a tab off the switcher births a normal window at the pointer; dropping a tab onto another window's deck/head merges it. Open decision: a mixed window shows the active tab's glyph, and each app's dock dot lights while any window holds one of its tabs.
T4Keyboard. ⌘T new tab · ⌘W closes the tab (the window when it's the last) · ⌃Tab / ⌃⇧Tab cycle · ⌘1–9 jump · ⌘[ back inside the active tab. All reachable via ⌘K.
T5State persists per space — tab set, order and active index join window rects in desktop-state (S11).
T6Splits compose. Each split pane owns its tab set, cmux-style; the window head follows the focused pane. The deck is the canonical compact form — A and C both degrade to it where space runs out.

Recommendation — B · Deck. It is the cmux model you pointed at, it preserves the entire existing head contract per tab (breadcrumbs and route tabs included, which A sacrifices), and it scales to a realistic ceiling with a graceful overflow. C is the strongest future layer — same data model projected vertically, worth shipping later as a rail toggle on top of B for session-heavy windows; its narrow fallback is already B's deck. A is a density mode, not a foundation: two contract amendments for a ~5-tab ceiling.
