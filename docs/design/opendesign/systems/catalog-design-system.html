Catalog design system

Specs, live examples, and class contracts for AGH inventory listings — Loops, Vault, Skills, Bridges, and similar catalogs. Extracted from loops-catalog.html and vault-redesign.html, aligned with LISTING-STANDARD.md and packages/ui tokens.

Principles

01

Rules that keep every inventory page feeling like the same product — not a collage of one-offs.

Default

Rows first

Default view is always rows. Cards are for browse/install density. Persist view=rows|cards in the URL.

Chrome

Search + Filters ··· Rows|Cards

The listing toolbar owns discovery. Search lives before Filters — never in the topbar. View toggle is a PillGroup, never accent-filled.

Restraint

State via color only

Hover = --row-hover. No lift, no side-stripes, no gradients on rows/cards. Kind tags are neutral Pill xs (sans); ids stay mono.

Title pattern (locked)

Page head title + count, then the listing toolbar: [ Search ] [ Filters ] …… [ Rows | Cards ]. Do not invent a second segmented control for kind/category when Filters already cover them.

Redesign checklist

11

Run this before shipping any new inventory page in the web app.

  • P0 Topbar = icon + title + count | ghost + primary, both sm 22px (no breadcrumb, no search)
  • P0 Toolbar = Search → Filters → spacer → PillGroup Rows|Cards
  • P0 Default view is rows; URL persists view
  • P0 No accent side-stripes, gradients, or hover-lift on rows/cards
  • P0 Kind/type uses Pill mono neutral (sessions namespace → info)
  • P1 Cards: eyebrow under title; type in footer; desc only if meaningful
  • P1 Empty states for zero inventory and no-match
  • P1 Search AND-combined with filter chips; / focuses search
  • P2 No “Sorted by …” without a real sort control
  • P2 No second segmented control duplicating a Filter field
