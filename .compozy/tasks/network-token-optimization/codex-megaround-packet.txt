PRODUCT FRAME (decided by the operator — these are constraints, not options)
--------------------------------------------------------------------------------------------------

AGH separates two planes:

- CONVERSATION PLANE (network channels/threads): collaborative and cheap. Threads exist for deciding,
  reviewing, analyzing, planning, and discussing. Agents respond in a short, conversational register.
  Read-only lookups to answer a question are fine; heavy or mutating execution is NOT done in threads.
- EXECUTION PLANE (kanban tasks + autonomy kernel): owns real work. When a thread conversation produces
  actionable work, it is PROMOTED into a kanban task carrying a compact digest + pointer back to the
  thread. The kernel orchestrates execution — including fanning one task into N sub-runs of the SAME
  agent definition with DIFFERENT designation briefs — and compact status flows back into the
  originating thread as conversation.

The bridge between the planes is first-class and agent-manageable. The golden register rule that must
reach agents through guidance: "threads are for deciding and discussing — reply short and conversational;
when actionable work emerges, promote it to a task and link the card; do not execute inside the thread."

A. CONVERSATION-PLANE EFFICIENCY

A1. Channel activation policy (the "never a black hole" fix — reverses Round 1's zero-delivery default
    as an explicit hard cut):
    - New store-backed per-channel setting fanout_policy: 'capability_match' (DEFAULT) | 'coordinator' |
      'all_members'. Persist on network_channels (migration v44; map 08 area 1 has all four SQL
      touchpoints + NetworkChannelEntry + validation + PATCH route precedent).
    - Activation evaluation inside the delivery-set computation (router.go deliveriesFromLocalPeers, the
      site map 08 pins): for an UNADDRESSED thread message with no recorded participants, evaluate the
      channel policy instead of returning zero deliveries.
    - capability_match: deterministic, no-LLM matcher (new internal/network/activation.go) tokenizing
      SayBody.Intent (fallback Text) against each LocalPeer.CapabilityCatalog ID/Summary using the
      existing containment primitives (matchesWhoisQuery family). Top-K bounded (K configurable,
      sensible default 3). If no match → digest fallback to thread/channel members — NEVER silently
      nothing, NEVER all-members full injection.
    - coordinator: route the message as a full injection to the channel's coordinator peer. You must
      design the coordinator signal (none exists on PeerCard/LocalPeer today — map 08 flags it):
      prefer an explicit capability tag or channel-settings field over name conventions. The
      coordinator's job in conversation is triage: answer, pull in peers via mentions, or promote to task.
    - all_members: today's full fan-out, for small channels that opt in.
    - Mentions always override policy (see A2). Policy decisions must be observable (audit/log/hook —
      including which peers were activated and why) and agent-manageable (see A4 verbs + PATCH).

A2. Mentions (multi-target addressing):
    - Add Envelope.Mentions []string. KEEP To (it drives DirectRoomIdentity and directed semantics) —
      mentions are thread-plane multi-target addressing; map 08 lists the full blast radius
      (envelope/validate/router/cloneEnvelope/parseEnvelopeSummary/promptNetworkMeta/XML attrs/
      networkLogFields/contracts/CLI --mention/tool schema/tests/docs). Mention-only envelopes stay on
      the broadcast subject with receiver-side filtering (subjectForEnvelope must NOT flip to
      DirectSubject).
    - Mentioned peers get full injection and become thread participants (upsert like peer_to in Round 1).

A3. Delivery composition diet + digest batching (slices 03 + map 08):
    - Suppress protocolGuidanceText after first successful exposure per session with a DURABLE ledger
      (survives reconnect/dropSession — Round 1's in-memory taper resets today).
    - Collapse the reply-flags prose: verify first whether PromptNetworkMeta reaches model-visible
      context across provider adapters; if it does not, keep ONE compact line referencing the ids in the
      message metadata instead of the ~400 B flag enumeration. Design honestly around what you verify.
    - Stop double-encoding say bodies: plaintext only for chat say; base64 body only for structured kinds
      (capability/receipt/trace) where exact-bytes fidelity matters. Preserve an observability path for
      canonical bytes (audit already stores them).
    - Digest delivery mode: new DeliveryMode "digest" + a multi-envelope digest formatter (renderer is
      strictly per-envelope today). Used for (a) policy digest-fallback (A1) and (b) coalescing a
      backed-up per-session queue into one turn while preserving per-message ids for reply/causation.
      Rework prompt-cost attribution (recordThreadPeerPromptCost assumes 1 delivery = 1 envelope) so
      digest turns attribute cost honestly across the coalesced envelopes.
    - Extend injected-body caps for non-say kinds (greet/capability precedent: greet_summary 160-rune cap).

A4. Volume verbs + subscriptions:
    - New network_subscriptions store (migration v45) keyed (workspace_id, channel, thread_id, peer_id)
      with mode mute|digest|full + optional keyword filters. Daemon-side, zero-token evaluation at the
      delivery-set site (resolver-interface precedent: ThreadParticipantResolver injection).
    - Verbs with three-surface parity (native tool + CLI + HTTP/UDS): mute / unmute / subscribe /
      digest-mode per channel and per thread. Workspace-scoped; hook-observable.
    - Channel settings PATCH (fanout_policy + defaults) for operators AND agents.

A5. Response-register shaping (slice 06 — operator-mandated):
    - One short surface-aware register line inside the per-delivery guidance, riding the existing
      verbose→compact taper (do NOT re-inflate what A3 just cut — budget the line).

B. TWO-PLANES BRIDGE

B1. Thread→task promotion (first-class verb, three-surface parity):
    - Extend the task-create path so a task can carry a typed thread origin: channel, thread_id,
      originating message id, and a byte-budgeted pin-and-trim digest (enforceTaskContextBudget
      precedent) + pointer. Never full-history replay.
    - Wire the network ingress: CreateTaskFromPeer exists, is capability-gated, and has ZERO non-test
      callers — add the wire dispatch that reaches it, mirroring withNetworkRunMetadata to stamp trusted
      thread metadata server-side.
    - Surfaces: native tool (agh__task_promote_from_thread or equivalent), CLI (agh task promote), HTTP
      (thread-scoped promote route). Promote CREATES a task (kanban card) — it does not auto-execute
      unless it goes through the explicit enqueue path (respect Task.AutoEnqueueOnReady semantics).
    - Web: the thread view exposes promote + shows the linked card; the kanban card links back to the
      thread (scope web work to what the changed contracts require plus these two affordances).

B2. Status-back:
    - A network status-back EventObserver registered in composeTaskEventObserver, imitating
      bridgeTerminalTaskNotificationObserver (filter, de-dupe, deliver): on meaningful transitions of a
      thread-originated task, post ONE compact conversational message into the originating thread
      (state, run id, blocker/next action, artifact link) following the Communication Discipline register.
    - Design the missing primitive: daemon-originated network message injection (Manager.Send is
      session-bound today). Prefer an explicit system/runtime peer identity that is first-class and
      observable (identity/proof rules in internal/CLAUDE.md apply) over impersonating any session.

C3. Budgets + stop: per-run budget caps (new state — design the minimal honest shape; RuntimeLimits and

C5. Surfaces + guidance: fan-out reachable via task tool/CLI/HTTP surfaces (parity), and
