# ADR-001: Attribute ACP Mock Diagnostics with the Existing AGH Session ID

## Status

Accepted

## Date

2026-07-13

## Context

The ACP mock driver writes newline-delimited diagnostics to one file per registered fixture agent.
More than one daemon-owned ACP process can use that registration concurrently. Each process creates
its own ACP session identifier sequence, so two processes can both emit an identifier ending in
`session-1`. The full runtime E2E lane demonstrated this collision when a user session and a memory
extractor session wrote reasoning negotiation records to the same file.

The session manager already injects the stable, daemon-owned `AGH_SESSION_ID` into every ACP
subprocess. The diagnostics harness currently discards that owner and therefore cannot attribute a
record to the session returned by the public API.

## Decision

Every diagnostics record written by `acpmock-driver` carries the trimmed process environment value
`AGH_SESSION_ID` as `agh_session_id`. The driver stamps the value inside its single diagnostics
writer so lifecycle, protocol, and prompt records cannot diverge.

The `acpmock` package exposes one exact, order-preserving filter for this owner. Session-specific
E2E assertions filter by the AGH session ID returned by the API before applying projections such as
`ProtocolDiagnostics`. An empty requested owner matches no records.

The shared per-agent JSONL remains the diagnostics transport. This keeps concurrent-process
behavior observable and proves attribution instead of avoiding it.

## Alternatives Considered

### Alternative 1: Filter by the ACP session ID

- **Description**: Select diagnostics using `DiagnosticsRecord.SessionID`.
- **Pros**: Requires no record shape change.
- **Cons**: ACP session IDs are process-local in the mock driver and collide across subprocesses.
- **Why rejected**: Two independent processes can both emit the same ACP session ID, which is the
  confirmed BUG-0036 root cause.

### Alternative 2: Disable background memory work in the E2E fixture

- **Description**: Prevent the memory extractor from starting while reasoning negotiation runs.
- **Pros**: Removes the immediate competing writer.
- **Cons**: Weakens the runtime scenario, hides valid concurrency, and does not fix attribution for
  any other daemon-owned process.
- **Why rejected**: It is a test workaround rather than a root-cause fix.

### Alternative 3: Allocate one diagnostics file per ACP process

- **Description**: Generate a unique file path for each subprocess and aggregate files in the test.
- **Pros**: Physically isolates writers.
- **Cons**: Requires a new path-allocation and discovery protocol between the registration harness
  and every spawned process, while no longer exercising the shared-file behavior that failed.
- **Why rejected**: The existing AGH session owner is sufficient and produces a smaller, more
  faithful contract.

### Alternative 4: Add a new production invocation identifier

- **Description**: Extend ACP launch or sandbox contracts with another correlation value.
- **Pros**: Provides a purpose-built identifier.
- **Cons**: Duplicates `AGH_SESSION_ID` and widens production contracts to solve a test-harness gap.
- **Why rejected**: Production already owns the exact stable identity required by the assertion.

## Consequences

### Positive

- Concurrent diagnostics remain in one evidence stream but become exactly attributable.
- Reasoning E2E assertions use the public API session identity rather than a process-local surrogate.
- The fix covers lifecycle, protocol, and prompt records through one writer boundary.
- No production API, persistence, configuration, or extension contract changes.

### Negative

- Directly launched mock drivers that do not receive `AGH_SESSION_ID` emit unowned records.
- Session-specific assertions must explicitly apply the owner filter before semantic projections.

### Risks

- A future caller could forget the filter. The canonical reasoning regression and the concurrent
  same-fixture E2E make unfiltered session assertions fail by record count.
- Empty owner input could accidentally select unowned records. The filter is fail-closed and returns
  no records for an empty requested owner.

## Implementation Notes

- Add `AGHSessionID string` with JSON name `agh_session_id` to `DiagnosticsRecord`.
- Stamp the field in `mockAgent.writeDiagnostics` from `os.Getenv("AGH_SESSION_ID")` immediately
  before marshaling; caller-provided values never override process ownership.
- Add `DiagnosticsForAGHSession(records, aghSessionID)` in `internal/testutil/acpmock`.
- Hard-cut successful reasoning assertions to filter with `SessionPayload.ID` before calling
  `ProtocolDiagnostics`.
- Preserve the existing single `O_APPEND` write per JSONL record.
