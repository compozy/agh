## Verdict: "loop-engineering vs /goal vs loops spec" (2026-07-01, refined)

- CORRECTION to earlier framing: Hermes does NOT orchestrate via `/goal`. `hermes_cli/goals.py` (the Ralph loop) is SINGLE-SESSION multi-turn autonomy: re-pokes the SAME session with a continuation user-message (warm cache, no system-prompt mutation), judge emits done/continue/wait (fail-OPEN to continue, turn budget backstop). Multi-step ORCHESTRATION in Hermes = kanban board + delegation (spawns FRESH child sessions, parent just waits+collects, no goal loop over children) + cron (standalone runs, zero goal-loop integration). So "Hermes usa loop-engineering fortemente para orquestração" is imprecise.
- "loop engineering" (concept, per research corpus) ≠ `/goal`. It is the OUTER-HARNESS layer: triggers (cron/webhook/agent) + shared typed artifacts + per-loop README contracts + read-only verifier agents + cross-loop signal coordination. Ralph loop < inner harness < outer harness (loop-eng) < orchestration layer (DAGs/Symphony). The research topic itself is still RAW corpus (empty wiki/concepts) — "not strongly done" is true of the ARTIFACT, not the concept.
- The corpus's most rigorous source (`fromagentloops-todeterministicgraphs`) argues FOR a shift from prompt-lineage (agent loops) TO execution-lineage (deterministic graphs). The AGH loops spec IS that execution-lineage answer — it is the mature side of the very tension the corpus names, not a naive omission.
- What loops FORBIDS is narrow: goal loop INSIDE a node (analysis/08:222). It does NOT forbid loop engineering; loops is the orchestration-layer implementation of it. No real contradiction: Hermes `/goal` (prompt-lineage, single-session, re-poke) and AGH loops (execution-lineage, multi-node durable task_runs, statically-terminating) are DIFFERENT LAYERS.
- DECISION: do NOT redirect the loops spec (two-touch + 6 peer rounds; deterministic-terminate is load-bearing). The residual gap stays a SIBLING feature: a cheap single-session "keep re-poking until done" primitive (generations=fresh task_run throws away warm cache + context continuity each gen). Options: (a) node re-attempt "resume-in-session" mode; (b) session-level goal mode. Plus optional non-breaking DSL augmentation: Hermes 5-field contract (outcome/verification/constraints/boundaries/stop_when) fed into worker+judge (goals.py:252).
